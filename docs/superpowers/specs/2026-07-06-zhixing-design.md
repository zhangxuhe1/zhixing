## 1. 产品概述

### 1.1 一句话定位

一张有故事的中国地图——**读懂每个地方的风土人情，留下你走过的痕迹。**

对用户表述：「去一个地方之前，来这里读懂它；离开之后，把你的故事留在这里。」

### 1.2 项目性质与目标

- **性质**：独立开发者产品。认真上线、获取真实用户、争取收入，初期单人开发。
- **质量标准**：借助 AI 辅助开发提效，从第一天按商业化质量做（架构不留返工债），功能按反馈节奏分批上线。
- **验证路径**：先小范围内测（TestFlight），收反馈迭代，再公开上架。
- **范围**：内容以中国地区为主，全球留待后续；合规事项后置到公开上线前（见第 5 章）。

### 1.3 产品结构：双层地图

产品即一张中国地图，叠两层内容：

- **人文层（知）**——官方内容，AI 生成 + 人工精修：每个地方的风土人情、方言、掌故，以「风物卡」形式故事化呈现。解决**冷启动**：用户第一天打开就有东西可逛。
- **足迹层（行）**——用户内容：用户把自己在某地的故事和照片钉在地图上，默认私密、可选公开。解决**留存与付费**：记忆资产越存越厚。

两层的结合是本产品的独特价值：**了解一个地方的魂，再留下自己的痕迹。** 拆开任何一半都会退化为平庸产品（纯内容站或普通足迹工具）。

### 1.4 使用主线与辅线

- **主线：旅行前后的仪式**——行前逛目的地人文层做功课 → 行中/行后在足迹层记录 → 日积月累形成个人人文足迹地图。
- **辅线：云逛地图**——无旅行计划时随手逛各地风物。旅行是低频行为，云逛是高频填充，两者互补解决旅行类产品的留存死穴。

### 1.5 目标用户

1. **主力：文化感旅行者**。25–40 岁，City Walk / 博物馆 / 古镇人群，旅行时在意"这地方有什么讲究"。已在用小红书查攻略但嫌其嘈杂商业化；照片攒了一相册从没整理过。iPhone 用户占比高，有付费习惯。
2. **次级：恋地者**。离乡者云逛家乡、对特定地域有感情的人。云逛辅线与方言内容的核心受众。

**刻意不服务**：找攻略比价的实用主义游客（小红书/马蜂窝更合适）；想涨粉带货的内容创作者（本产品无关注、无评论、无流量分发，此类用户自然离开——这是设计意图）。

### 1.6 与竞品的差异

| 竞品 | 它们是 | 知行是 |
|------|--------|--------|
| 小红书/马蜂窝 | 攻略与种草的流量场 | 无流量机制的人文阅读与私人记录 |
| 一生足迹/世界迷雾/Polarsteps | 打卡统计工具 | 足迹之上叠加"读懂此地"的人文层 |
| 百科/地方志公众号 | 资料式罗列 | 故事化、地图化、与个人足迹交织 |

## 2. 功能设计

### 2.1 地图主界面

- **打开即地图，无信息流、无首页 feed。**
- 人文层随缩放层级展开：缩得远见省份/文化区，拉近浮现城市、古镇、街区的风物点。
- 足迹点与风物点可分层显隐；点位聚合（clustering）必做。
- 顶部搜索（地名直达）；「随便走走」按钮随机飞往一个有内容的地方（云逛入口）。
- 「留下足迹」常驻入口。

### 2.2 人文层：风物卡

- **一张卡 = 一个主题的小故事**，300–500 字 + 配图，五个分类：**习俗、吃食、方言、掌故、地名由来**。
- **内容块结构**：卡片由有序内容块组成，块类型为 `text` / `image` / `audio` / `video`。初期只生产文字与图片块，音频（方言卡）与视频块为运营期预留，数据结构第一天就支持。
- **状态机**：`AI 生成 → 已复核 → 下架`。「AI 生成」状态的卡可直接上架，卡面带「AI 整理·待复核」标识；人工复核后标识消失。
- 卡片底部：可折叠的**参考来源**（可信度差异化）+ **报错入口**。
- 卡片可**收藏**，行前收藏自动形成"这趟旅行的功课清单"。

### 2.3 足迹层

- **留下足迹**：地点（默认定位或从照片读取）+ 照片若干 + 一段话 + 日期。行中随手记，交互越快越好。
- **相册批量导入**（核心卖点 / aha 时刻）：读取相册照片 EXIF 坐标，把历年旅行照片按地点自动聚类，生成足迹草稿供用户确认——装上第一天，过去十年的足迹地图瞬间点亮。
- **我的足迹地图**：个人视角地图，去过的地方点亮，附统计（城市数/省份数等）。
- **公开机制**：默认私密（铁律）。单条足迹可设公开：文字（若有）进入该地点的「旅人故事」区，照片（若有）进入「旅人镜头」照片墙。想只公开照片，就发一条只有照片的足迹——不设更细的权限开关。
- **互动只有两样**：点亮（❤）与浏览数。无评论、无关注、无私信、无转发。

### 2.4 地点抽屉（点击地点后弹出，三段式）

1. **风物卡**（官方人文内容）
2. **旅人故事**（公开足迹的叙事区，按时间排列）
3. **旅人镜头**（照片墙：该地点所有公开足迹照片的聚合视图）

照片墙护栏：**按时间/季节分组，不按热度排序**；不设评论；公开照片抹除精确 EXIF，位置模糊到地点级——防"晒图流量场"化。

### 2.5 旅程小结（增长引擎）

一次旅行结束后自动生成「旅程小结」分享长图：此行去了哪、留了几段故事、精选配图，带 App 二维码，可发朋友圈/小红书。**站外分享图是本产品的主要增长机制**（独立开发者不买量）。

"一次旅行"的自动划界算法（连续日期 + 异地判定）细节见开放问题 Q7。

### 2.6 界面信息架构

```
知行 App
├── 地图主界面（启动即达）
│   ├── 人文层点位 / 足迹层点位（可切换显隐，自动聚合）
│   ├── 搜索（地名）
│   ├── 随便走走（随机飞行）
│   ├── ［+］留下足迹
│   └── 地点抽屉
│       ├── 风物卡（官方）
│       ├── 旅人故事（公开足迹）
│       └── 旅人镜头（照片墙）
├── 风物卡详情（内容块渲染 / 来源折叠 / 收藏 / 报错 / AI 标识）
└── 我的
    ├── 我的足迹地图（点亮 + 统计）
    ├── 足迹管理 / 相册批量导入
    ├── 收藏（行前功课清单）

```

### 2.7 刻意不做的功能

| 不做 | 理由 |
|------|------|
| 评论、关注、私信、转发、粉丝 | 定位为人文阅读+私人记录，非社区；同时把审核与运营负担降到单人可承受 |
| 信息流/推荐 feed | 地图即入口，拒绝流量分发逻辑 |
| 攻略、比价、预订 | 让给小红书/马蜂窝，不正面竞争 |
| 广告、内容付费墙 | 见商业化章节承诺 |

## 3. 内容策略

### 3.1 生产管线（五步）

1. **选题**：每地区按五分类建选题清单。AI 联网检索给候选，人工挑选——"什么值得写"不外包给 AI。
2. **资料收集**：AI 汇集地方志、百科、地方文化文章，强制标注每条信息来源。
3. **初稿生成**：按「风物卡写作模板」（见 3.3）批量生成。
4. **人工精修**：对照来源抽查事实、删 AI 腔、补个人观察。质量线：宁缺毋滥。
5. **上架与迭代**：来源折叠区公开；用户报错进入后台处理队列。

### 3.2 开发与审核并行

- AI 生成的卡**直接上架**（带「AI 整理·待复核」标识），开发与数据灌入不等待人工审核。
- 人工在管理后台异步复核，复核完成去除标识。
- 护栏：**公开发布（M4）前**，深做城市（北京）的卡应全部过人工复核；其余地区可继续带标识上线，透明标注 + 报错入口兜底。

### 3.3 风物卡写作模板（生成规则）

- 开头禁百科腔（禁止"XX 是一种…"式定义句），以场景、人物或对话切入。
- 300–500 字；至少一个**细节锚点**（具体店名/人名/年代/俗语原文/数字）——防同质化的关键。
- 传说与史实分开表述：不确定的用"相传""一说"标注。
- 至少 1 条参考来源，附卡底。
- 方言卡：词条 + 注音（拼音近似）+ 例句 + 使用场景小故事。
- 结尾不总结、不升华（"这正是……的体现"属 AI 腔，禁止）。

**示例卡**（吃食 · 北京）：

> **卤煮火烧：从宫里逃出来的穷人乐**
>
> 天还没亮透，南横街的小肠陈门口已经排上了队。大锅里咕嘟着小肠、肺头、炸豆腐，老汤面上浮着一层亮油，师傅拿铁钩子捞起火烧，刀起刀落，"井"字四刀，浇一勺老汤，撒蒜泥韭菜花。
>
> 一说卤煮的祖上是宫廷的"苏造肉"——乾隆年间苏州厨子张东官进御膳房，用五花肉加丁香、官桂等九味香料炖肉，后来流入民间。五花肉贵，拉车的脚夫吃不起，摊主改用猪下水，没想到歪打正着，成了北京城最扎实的一口平民吃食。老北京人管这叫"穷人乐"，乐就乐在：一碗下去，肉、主食、汤，全齐了。
>
> *参考来源：《北京志·商业卷》；小肠陈非遗申报材料（示例）*

### 3.4 首批范围：「1 + 6 + N」

| 梯队 | 地区 | 每地卡量 | 说明 |
|------|------|---------|------|
| 深做 1 城 | 北京 | 20–30 | 样板间：覆盖市区街巷与周边，展示产品完全体 |
| 熟悉 6 地 | 山东德州、山东济南、广东东莞、香港、澳门、河南商丘 | 各 8–12 | 产品所有者熟悉的地区；方言横跨冀鲁官话、粤语、中原官话；德州/商丘等非旅游热门地正体现"每个地方都有风土"的产品理念 |
| 全国撒点 N | 其余省级行政区 | 各 3–5 | 保证"随便走走"与查家乡不落空 |

- 总量约 200 张卡；人工精修按每卡 20–30 分钟估算，**总人工投入约 80–100 小时**（这是本产品最大的隐性成本，如实记录）。因 3.2 的并行策略，此投入不阻塞开发进度。
- 分批灌入：第一批约 120–130 张（北京 + 六地 + 10 个热门省份撒点），其余第二批补齐。

### 3.5 地点层级与地点库

- 四级：**省 → 市 → 区县/古镇/街区 → 具体点位**。初期主要挂"市"与"古镇/街区"两级。
- 地点库手工维护（几百个起步），不接全量 POI 数据库。

### 3.6 方言内容分期

- 初期：文字方言卡（词条+注音+例句+讲究）。
- 运营期：启用音频块；"用家乡话说句欢迎"UGC 征集活动，既是内容来源又是运营事件（机制见开放问题 Q4）。

### 3.7 按需扩展机制

后台记录"搜索了但无内容"的地点日志，按真实需求补内容，不盲目铺量。

## 4. 技术方案

### 4.1 组件全景（四个）

| 组件 | 技术 | 职责 |
|------|------|------|
| iOS App | SwiftUI + MapKit | 主产品。MapKit 中国区底图即高德数据，免费且合规；自定义标注 + 聚合渲染 |
| 后端 API | Node.js（Fastify + Prisma）+ PostgreSQL + 对象存储 + CDN | 单体服务：内容、足迹、用户、计数、审核状态 |
| 管理后台 | Next.js（与后端同仓库） | 风物卡管理（状态机/批量导入 AI 结果）、地点库维护、UGC 审核队列、报错处理。够用即可，不追求好看 |
| 内容管线 | TypeScript 脚本 | AI 检索 + 按模板生成初稿，写入后台为「AI 生成」状态 |

**语言决策**：TypeScript 全栈（后端/后台/管线一种语言，单人上下文切换成本最低，AI 辅助编码支持最好）。备选：若管线复杂化，可单独切 Python，不影响主体。

**服务器策略**：内测期用香港/海外节点（域名免备案，即开即用）；公开上线前迁回国内云并完成 App 备案（见 5.2）。

### 4.2 核心数据模型（概念级）

| 表 | 关键字段 | 说明 |
|----|---------|------|
| `place` | 名称、层级、父地点、坐标、简介 | 地点库，手工维护起步 |
| `card` | place_id、分类（五类）、标题、状态（ai_generated/reviewed/retired）、来源列表 | 风物卡 |
| `card_block` | card_id、顺序、类型（text/image/audio/video）、内容或媒体 URL | 多媒体预留在此落地 |
| `footprint` | user_id、place_id、文字、日期、可见性（private/public）、审核状态 | 足迹 |
| `footprint_photo` | footprint_id、媒体 URL、拍摄时间、脱敏后位置 | 公开展示时抹除精确 EXIF |
| `user` | Apple ID 标识、昵称 | Sign in with Apple，不收手机号 |
| 计数 | 点亮、浏览 | 轻互动 |

### 4.3 关键机制

- **相册导入**：读 EXIF 坐标 → 自建地点库半径匹配（Apple 反地理编码兜底）→ 按地点聚类生成足迹草稿 → 用户确认入库。
- **UGC 审核**：内测期，公开内容先进后台人工队列，审过才对他人可见（量小可行，零外部依赖）；公开上线后，接云厂商内容安全 API 机审 + 人工复核 + 举报入口。

## 5. 隐私与合规

### 5.1 隐私设计原则

- **默认私密**是铁律：一切足迹默认仅自己可见，公开是逐条主动选择。
- 公开时：抹除照片 EXIF（设备信息/精确坐标），展示位置模糊到地点级；公开前预览提醒（人脸、车牌、门牌）。
- 权限克制：定位"仅使用期间"；相册用 iOS 选择性访问；登录仅 Sign in with Apple。
- **数据是用户的**：支持一键导出全部足迹与照片（信任承诺，也是 Pro 功能之一）。

### 5.2 公开上线前合规清单（内测期全部无需，按序办理）

1. 注册主体（个体户即可起步）
2. App 备案（工信部，云厂商可代办；服务器此时迁回国内）
3. 接入内容安全机审 API + 举报功能 + 审核记录留存
4. 隐私政策、用户协议、个人信息收集清单与第三方 SDK 清单
5. 若上安卓：软件著作权 + 各商店资质

地图使用 MapKit/高德 SDK，测绘合规自动满足，无需自有资质。

## 6. 商业化：「知行 Pro」订阅

### 6.0 商业化原则（先于一切细节）

1. **内测期（M0–M2）全功能免费**：不配置内购、不设任何额度限制。内测验证的是产品价值，付费意愿在 M3 用访谈验证。
2. **免费/Pro 边界不写死在代码里**：客户端只判断"是否拥有权益 X"，权益与免费/Pro 的映射由服务端配置下发。调整边界 = 改配置，无需发版。本章全部表格内容均为**可随时调整的假设**，非承诺。
3. **创始用户回馈**：公开上线时，向内测用户赠送长期 Pro 权益——既是感谢，也避免"内测免费、上线收费"的落差反感。

| | 免费版 | Pro |
|---|--------|-----|
| 人文层内容 | **永久全免费**（内容是获客资产，不设墙） | 同左 |
| 足迹记录 | 宽松额度（数值待内测定，见 Q2） | 无限 |
| 相册批量导入 | 限最近一年（首次导入的 aha 体验设计见 Q9） | **历史全量** |
| 旅程小结 | 基础模板 | 高级模板 |
| 数据导出 | — | 全量导出 |
| 离线收藏 | — | ✓ |

- 定价假设：¥12–18/月、¥98–128/年，内测后定档；可加大额买断档（独立开发圈用户偏好，见 Q8）。
- **永不做**：广告、出售数据、内容付费墙。

## 7. 路线图（里程碑制）

| 里程碑 | 范围 | 过关标准 |
|--------|------|---------|
| **M0 地基** | 后端 + 数据模型 + 管理后台骨架 + 内容管线跑通；北京首批卡灌入 | 管线日产 10+ 张 AI 卡 |
| **M1 内测一 · 核心闭环** | 地图逛人文层、搜索、随便走走、留足迹、相册导入、我的足迹地图；TestFlight 10–30 人 | 用户自发导入相册并反复翻看自己的地图（aha 验证） |
| **M2 内测二 · 公开与分享** | 公开足迹、旅人故事、照片墙、点亮、审核队列、旅程小结分享图；扩至 50–100 人 | 公开率、分享图外发率 |
| **M3 公开准备** | 合规清单执行、内容扩至 1+6+N 全量、付费墙（首次引入，边界走服务端权益配置，见 6.0）、性能与体验打磨 | 内测用户付费意愿访谈 |
| **M4 公开发布** | App Store 上架；小红书/即刻发布产品故事，启动自然增长 | 自然增长与留存数据 |

## 8. 风险与开放问题

### 风险

| # | 风险 | 缓解 |
|---|------|------|
| R1 | 内容边际成本：200 张卡只是首批，扩城市成本持续 | AI 管线摊薄；搜索缺失日志按需补（3.7）；UGC 补充 |
| R2 | 留存假设未验证："云逛是否真高频"是最大产品假设 | M1/M2 数据回答；备选手段见 Q1 |
| R3 | iOS-only 流失安卓用户；记录型产品有换机迁移焦虑 | M4 后依数据定跨端策略（Q3）；数据导出降低迁移焦虑 |
| R4 | 大厂/竞品模仿 | 做深调性与情感资产：小众深爱 > 大众浅用；个人数据沉淀即迁移成本 |
| R5 | AI 内容事实错误损伤可信度 | 状态标识透明 + 强制来源 + 报错入口 + 深做城市上线前过人审 |

### 开放问题（后续讨论清单）

- **Q1**：要不要做克制的「今日风物」每日推送？（留存手段 vs 打扰）
- **Q2**：免费版足迹额度的具体数值（内测数据定）
- **Q3**：安卓/跨端的时机与技术路线（KMP / Flutter / 继续原生）
- **Q4**：方言音频 UGC 征集的质量控制机制
- **Q5**：「知行」App Store 重名与商标查重（上架前必办）
- **Q6**：第 2、3 个深做城市选谁（依内测用户分布定）
- **Q7**：旅程小结的"一次旅行"自动划界算法（连续日期 + 异地判定的具体规则）
- **Q8**：买断档定价与权益边界
- **Q9**：相册全量导入既是新用户 aha 时刻（2.3）又是 Pro 权益（第 6 章），两者存在张力。候选方案：新用户首次全量导入免费、后续增量导入归 Pro——兼顾首次体验与付费转化，内测期验证

## 10. 关键决策记录（ADR 摘要）

| # | 决策 | 理由 |
|---|------|------|
| D1 | 双层地图合体（否决"纯内容"与"纯工具"方案） | 独特价值在两层结合：人文层解决冷启动，足迹层解决留存付费 |
| D2 | 轻社交：无评论/关注/私信/feed | 定位使然；单人可承受的审核运营负担；避开小红书正面竞争 |
| D3 | AI 卡直接上架带「待复核」标识，人工异步复核 | 开发不被内容阻塞；透明标注兜住可信度 |
| D4 | 人文内容永久免费，工具功能收费 | 内容是获客资产；付费点落在个人记忆资产的工具价值上 |
| D5 | iOS 优先 + MapKit | 目标用户 iPhone 占比高；MapKit 中国区即高德底图，免费合规 |
| D6 | 内测服务器海外、公开上线前迁国内并备案 | 内测零合规阻塞，上线前一次性补齐 |
| D7 | TypeScript 全栈单体 | 单人项目一种语言通吃，切换成本最低 |
| D8 | 照片墙三护栏：规则从简/不按热度排序/EXIF 脱敏 | 防"晒图流量场"化，守住产品边界 |
| D9 | 「1+6+N」内容范围 | 样板间深度 + 熟悉地区可把控质量 + 全国不落空 |
| D10 | 默认私密铁律 + 数据可导出 | 信任是记录型产品的命根子 |
| D11 | 内测期全免费；免费/Pro 边界由服务端权益配置驱动，不写死在代码 | 商业化方案保持随时可调，内测反馈不被付费墙污染；创始用户获长期 Pro 回馈 |
