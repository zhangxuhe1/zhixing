# 地点库省市级联筛选 + 关键字搜索 设计

## 背景与目标

管理端「地点库」(/places) 随录入增长,现有的单一层级下拉不足以支撑日常维护——运营需要"看某省某市下都录了哪些点位、缺什么"。目标:省→市级联筛选圈定子树范围,叠加名称关键字定位具体点位,减少翻表格的维护成本。

## 方案取舍

- **纯前端级联下拉(选定)**:页面本就一次性拉全量地点,树关系已在内存;建 children 索引 + 子树收集即可,零 API 改动。几百到数千地点量级毫无压力。
- 树形展开表格:改动大、"看某市全部点位"要逐级展开,维护效率反而低,弃。
- 服务端查询参数:当前数据量属过度设计,地点上万再议。

## 交互与语义

筛选栏一行:`[省 ▾] [市 ▾] [层级 ▾(现有)] [关键字输入框] [新建地点(现有)]`。

- 省下拉:全部**链顶**节点(`parentId` 为空),按中文名排序——与服务端 trips/footprints 的链顶语义一致。直辖市/特区(北京市、香港)天然在列;层级非省的链顶属遗留脏数据,同样列出并带层级标注,保证整棵子树可达、可当场修复。
- 市下拉:所选省的**直接子节点**中 `level=CITY` 者,按中文名排序;未选省或所选省无市级子节点(直辖市)时禁用;换省自动清空已选市。
- 表格 = 最深已选节点的**整棵子树(含自身)** ∩ 层级筛选 ∩ 名称包含关键字(trim、大小写不敏感),三者 AND。含自身是为了选中某市时还能顺手编辑该市节点行。
- 编辑/新建表单打开期间四个筛选控件禁用(与新建按钮同规),避免行在编辑中途被筛掉造成"消失"错觉。
- 刷新(保存后 reload)使已选省市不再满足下拉数据源谓词时自动复位——否则 React 会把下拉重同步到首项显示、过滤却仍卡在旧根。
- 标题计数沿用现有 `shown.length`,自动显示过滤后数量。

## 实现要点

仅改 `apps/admin/app/places/page.tsx`:

- 子树判定:`parentById: Map<id, parentId>` + 沿父链上溯谓词(树深≤4,32 跳保险丝防御脏数据成环,与服务端 reachesSelf 同思路),不物化 children 索引与子树集合;
- 关键字经 `useDeferredValue` 降优先级过滤,逐键输入不阻塞;
- `load()` 成功时清除既往错误横幅;无新错误路径(纯内存过滤)。

## 已知取舍

- 保存后若行落在当前筛选范围之外,表格按筛选语义正常不显示该行(筛选条件可见、可自行清除);后续如需"保存后高亮/定位新行"再议。
- 直辖市市下拉禁用示意"无市级子层",细分靠层级/关键字。

## 验证

admin 无测试基建:`next build` 类型检查 + 人工走查(选省→选市→子树正确;直辖市;关键字与层级叠加;换省清市;编辑已选市改父后筛选自动复位)。另经 10 视角多代理评审 + 逐项裁决(2026-07-18),确认项已全部修复或记录于上。
