## 2. 数据模型

`Footprint.visibility / reviewStatus / likeCount / viewCount` 与索引 `[placeId, visibility]` 在 M0 已建，无需迁移。新增 4 表、改 1 表：

| 表 | 关键字段与约束 | 说明 |
|----|--------------|------|
| `Like` | userId + footprintId 唯一；createdAt | 点亮到人、可取消；`Footprint.likeCount` 在同一事务内原子增减（unique 冲突视为幂等 no-op） |
| `CardFavorite` | userId + cardId 唯一；createdAt | 卡片收藏 |
| `CardReport` | cardId、userId、text、status(OPEN/RESOLVED)、createdAt | 卡片报错，admin 处理 |
| `Trip` | userId、title、startDate、endDate、createdAt | 旅程小结持久化——只存元数据，分享图不落服务端 |
| `Footprint`（改） | 加可空 `tripId` 外键（onDelete: SetNull 方向为脱离而非删足迹） | 足迹归属旅程；删足迹自动脱离，不建关联表 |

## 3. 公开状态机

他人可见的**唯一判据**：`visibility = PUBLIC 且 reviewStatus = APPROVED`。

- 设公开 → `PUBLIC + PENDING`：进审核队列；他人不可见，本人可见并显示"审核中"。
- approve → `APPROVED`：进入旅人故事/照片墙。reject → `REJECTED`：本人显示"未通过"，编辑后可重新公开（回 `PENDING`）。
- **编辑已通过的公开足迹（改文字或日期）→ 自动回 `PENDING` 重审**（防审后偷换内容）。
- 撤回私密随时可；再次公开 = 重新进队列（不追踪"内容未变"哈希，宁严勿漏，运营量小可承受）。

## 4. 服务端 API

所有接口沿用 M1 登录鉴权；"公开"指对登录用户可见，无匿名访问面。

### 4.1 公开读（独立端点 + 专用 DTO，脱敏在类型层内建）

架构决策（已确认）：公开面与私密面**物理分离**——公开 DTO 只定义脱敏后字段，泄露需要"主动加字段"而非"忘记过滤"。

- `GET /places/:id/stories`（分页，按足迹日期倒序）：条目 = { footprintId, text, date, authorNickname, likeCount, viewCount, likedByMe, photos[{ photoId, url }] }。**禁止出现**：userId、appleSub、lat/lng、精确 takenAt。
- `GET /places/:id/photo-wall`：{ groups[{ label（"2024·春"）, photos[{ photoId, url, footprintId }] }] }。分组规则：季节按足迹 date 月份映射（3–5 春 / 6–8 夏 / 9–11 秋 / 12–2 冬），年取足迹日期年份。**护栏**：按时间分组倒序，无热度排序，不展示计数。

照片本体已无 EXIF（iOS 两条上传路径均经 `UIImage → jpegData` 重编码），精确坐标只存 DB 结构化字段——脱敏因此是响应裁剪问题，无图像处理管线。

### 4.2 互动

- `PUT /footprints/:id/like` / `DELETE /footprints/:id/like`：幂等；仅对"他人可见"状态的足迹可点。
- `POST /footprints/:id/view`：匿名累加，不记到人；与 like 同样仅对"他人可见"状态的足迹生效（其余 404）。服务端只做限流，精确防刷不在 M2；口径由客户端保证（点开全文/大图才报，session 去抖）。

### 4.3 足迹编辑（吸收 M1 债"编辑不落库"）

- `PATCH /footprints/:id`：属主校验；可改 text / date / visibility；触发 §3 状态机语义。

### 4.4 收藏与报错

- `PUT /cards/:id/favorite` / `DELETE /cards/:id/favorite`（幂等）；`GET /me/favorites`。
- `POST /cards/:id/report` { text }。

### 4.5 旅程

- `GET /me/trip-suggestions`：服务端运行划界算法（§7），纯函数、不落库，返回 [{ footprintIds, suggestedTitle, startDate, endDate }]。
- `POST /me/trips` { title, footprintIds } 确认落库（设置 footprints.tripId）；`GET /me/trips`；`PATCH /me/trips/:id`（改题、增删足迹 = 手动并/拆）；`DELETE /me/trips/:id`（仅解除归属，不删足迹）。

### 4.6 配置下发

- `GET /app-config`：{ shareLandingUrl }。分享图二维码指向，先占位，上架后改配置不发版（呼应规格书 6.0"不写死客户端"原则）。

### 4.7 admin API（沿用 ADMIN_TOKEN）

- `GET /admin/review-queue`（条目含照片 presigned URL——admin 鉴权下发，供队列页预览）；`POST /admin/review/:footprintId` { action: approve | reject }。
- `GET /admin/reports`；`PATCH /admin/reports/:id` { status }。

### 4.8 防滥用基础

- `@fastify/rate-limit` 全局限流；view/like/search 更严档。
- `/search`：q 长度 cap（≤64 字符）+ 限流（SearchMiss 写入面收口）。
- auth.ts 收窄 try 范围（DB 故障不再误报 401）。

### 4.9 服务端质量债吸收清单（M1 台账）

photos 字段 zod 化；`/me/stats` CTE 重写（去全表加载）；cardCount helper 去重；MinIO 用户名进 env；私密面足迹响应 select 裁剪（去 Prisma 超集字段）；补测试：presign 公网/内网回归、413 超限、无 CITY 祖先回退、devAuth-off 测试 app 传 s3Bucket。

## 5. iOS App

### 5.1 地点抽屉补全三段式（M1 仅风物卡段）

- **旅人故事** tab：公开足迹流（文字 + 缩略图 + 昵称 + 日期 + ❤ 点亮），点开单条读全文/大图时报浏览（session 去抖）。

### 5.2 公开流

### 5.3 互动、收藏、报错

- ❤ 乐观更新、失败回滚；卡片详情加收藏按钮 + 报错表单 sheet；Me tab 收藏列表页（行前功课清单）。

### 5.4 旅程小结（Me tab 入口）

- 建议分组列表（trip-suggestions）+ 已保存旅程历史。
- 确认页：并组 / 拆组 / 改标题 → 保存。
- 预览页：SwiftUI 基础模板（此行去了哪 / 几段故事 / 精选照片 ≤9 张 / 二维码指向 app-config 下发 URL）→ `ImageRenderer` 渲长图 → 系统分享 sheet（存相册/微信）。照片上界规避 ImageRenderer 内存风险；二维码用 CoreImage 本地生成。高级模板归 M3 Pro。

### 5.5 iOS 质量债专项（收尾任务，12 项）

## 6. 管理后台（够用即可）

- **审核队列页**：待审足迹列表（文字、照片预览、作者昵称、地点、提交时间），逐条 approve/reject，操作后出队。
- **报错处理页**：报错列表（关联卡片跳转 + 描述文字），标记已处理。

## 7. 旅程划界算法（关闭规格书开放问题 Q7）

已确认规则（服务端纯 TS 函数，vitest 全边界覆盖）：

1. **常驻城市判定**：足迹（按 CITY 层级归并）覆盖天数最多的城市为常驻城市；常驻城市足迹不参与成行。足迹总天数过少（< 7 天）不判常驻，全部参与。
2. **日期聚类**：其余足迹按日期排序，相邻间隔 ≤ 2 天归同一旅行（容忍旅途断更一天）。
3. **成行门槛**：分组内 ≥ 2 条足迹才输出为建议；单足迹组丢弃（用户可从足迹手动建旅程，不在 M2 强做）。
4. **建议标题**：城市 ≤ 2 个全列（"济南·青岛"），> 2 个取前 2 + "等 n 地"，后缀年月（跨月取起始月）："济南·青岛·2024年5月"。
5. 算法只出**建议分组**，确认页手动并/拆/改题兜底——不追求划界完美，内测收案例再调参。已知误判面：搬家/长住外地用户的常驻地漂移。

## 8. Seed 模拟数据（落 `packages/db`，与 Prisma 同居）

- **直插 PG + 直传 MinIO**（与 M1 测试基建同路数，不依赖 API 进程）；照片素材用 repo 内置十余张小尺寸 CC0 风景图循环。不造 EXIF——存储照片本无 EXIF，`takenAt/lat/lng` 直接写 DB 字段。
- **不调 LLM**：故事文案用内置语料模板组合生成（可重复、免 Key、CI 可跑）。
- 三档：`rich`（30 用户 / 数百足迹 / 各审核状态齐备 / 多地公开内容 / 含可划界的旅行日期序列）、`sparse`（3 用户 / 10 条公开足迹，冷启动验收档）、`--wipe`（清 UGC 保内容层）。
- 用户行直插（appleSub 用可识别前缀如 `seed-`，wipe 按前缀清理，不误删真实数据）；iOS 端可经 dev auth 旁路以这些 sub 登录，切换"别人"的视角查看公开内容。

## 9. 测试策略

延续 M1 约定：真 PG/MinIO，不 mock。重点面：

- **防泄露回归**：公开 DTO 响应断言"不得出现 userId/appleSub/lat/lng 字段"（对 M1 终审泄露教训的机制化）。
- 状态机流转：编辑重审、拒后重提、撤回再公开重新排队。
- 点亮幂等与并发计数一致性；view 累加。
- 划界算法纯函数全边界：常驻地判定、gap 边界（恰 2 天/3 天）、单足迹不成行、少足迹不判常驻、跨月标题。
- 限流生效（429 路径）。
- iOS 单测延续务实密度：划界建议的展示映射、公开状态徽标逻辑、分享图模板的数据装配。

## 10. 范围外（防蔓延）

举报入口与内容安全机审（M3 合规）；Pro 权益/付费墙/高级模板（M3）；评论/关注/私信/转发（永不做）；匿名公开访问（公开=登录可见）；浏览防刷精确化；安卓/跨端。

## 11. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 审核队列单人运营 | 内测 50–100 人 × 低公开率量级可控；部署后养成日清习惯；admin 队列页显示积压数 |
| ImageRenderer 超长视图内存 | 模板设精选照片 ≤9 上界；实现期实测长文本截断策略 |
| 划界误判（搬家/长住外地） | 手动并/拆兜底；suggestions 不落库，调参零迁移成本 |
| 模拟数据养出"永远有内容"错觉 | seed 稀疏档纳入验收流程（§5.1 空态） |
