# 知行 M2 服务端（内测二 · 公开与分享）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 M2 服务端全部能力：公开状态机与审核、脱敏公开读、点亮/浏览、收藏/报错、旅程划界与 CRUD、admin 两页、防滥用、M1 服务端质量债清偿、seed 三档模拟数据。

**Architecture:** 沿用 M1 单体 Fastify + Prisma + MinIO。公开面与私密面物理分离：新增 `routes/public.ts` 只装配脱敏 DTO；他人可见判据唯一收敛在 `src/visibility.ts` 共享常量。划界算法为纯函数独立于路由。seed 落 `packages/db`，直插 PG + 直传 MinIO。

**Tech Stack:** Fastify 5 + Prisma + PostgreSQL(5433) + MinIO(9000) + zod + vitest；admin 为 Next.js 15 + 纯 CSS；新增依赖仅 `@fastify/rate-limit`（api）与 `tsx`、`@aws-sdk/client-s3`（packages/db devDeps）。

**规格：** docs/superpowers/specs/2026-07-07-m2-design.md（含决策记录）；产品规格 docs/superpowers/specs/2026-07-06-zhixing-design.md

## Global Constraints

- **本计划只定义接口与行为，不含可粘贴的实现代码**（M1 台账教训：计划内嵌代码会把 bug 一并带入）。计划中的代码块仅限：Prisma schema 片段（声明式）、TS 类型/签名、端点契约、测试用例表。实现由实现者按契约编写，审查者按契约验收。
- 测试用真实 PG/MinIO，不 mock。前置：`open -a Docker`（如未跑）→ `pnpm db:up` → `pnpm -C packages/db push:test`。测试库 `postgresql://zhixing:zhixing@localhost:5433/zhixing_test`。
- pnpm 钉 `10.34.4`（勿动 packageManager 字段）；Node >= 22。
- commit 信息中文，尾行 `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`。
- 错误响应统一 `{ error: string, detail?: any }`；body 校验一律 zod，失败 400 `invalid_body`。
- 新增用户面端点一律 `{ preHandler: requireUser }`（`req.userId` 可用）；管理面一律 `{ preHandler: requireAdmin }`。
- **他人可见判据唯一**：`visibility=PUBLIC 且 reviewStatus=APPROVED`，只能通过 `src/visibility.ts` 的共享常量引用，禁止在路由内手写重复条件。

**Interfaces:**

- Produces: 模型 `Like`、`CardFavorite`、`CardReport`、`Trip`、枚举 `ReportStatus`，`Footprint.tripId`/`Footprint.publicRequestedAt`，后续所有任务经 `@zhixing/db` 的 Prisma 类型消费。

**Schema 增量（声明式契约）：**

```prisma
enum ReportStatus { OPEN RESOLVED }

model Like {
  id          String   @id @default(cuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  footprintId String
  footprint   Footprint @relation(fields: [footprintId], references: [id], onDelete: Cascade)
  createdAt   DateTime @default(now())
  @@unique([userId, footprintId])
  @@index([footprintId])
}

model CardFavorite {
  id        String   @id @default(cuid())
  userId    String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  cardId    String
  card      Card     @relation(fields: [cardId], references: [id], onDelete: Cascade)
  createdAt DateTime @default(now())
  @@unique([userId, cardId])
}

model CardReport {
  id        String       @id @default(cuid())
  cardId    String
  card      Card         @relation(fields: [cardId], references: [id], onDelete: Cascade)
  userId    String
  user      User         @relation(fields: [userId], references: [id], onDelete: Cascade)
  text      String
  status    ReportStatus @default(OPEN)
  createdAt DateTime     @default(now())
  @@index([status])
}

model Trip {
  id         String      @id @default(cuid())
  userId     String
  user       User        @relation(fields: [userId], references: [id], onDelete: Cascade)
  title      String
  startDate  DateTime
  endDate    DateTime
  footprints Footprint[]
  createdAt  DateTime    @default(now())
  @@index([userId])
}
```

`Footprint` 增两列 + 一索引：`tripId String?` + `trip Trip? @relation(fields: [tripId], references: [id], onDelete: SetNull)`；`publicRequestedAt DateTime?`（进审核队列时间，排序用）；`@@index([visibility, reviewStatus])`。`User`/`Card` 补反向关系字段（likes/favorites/reports/trips、favorites/reports）。

### Task S2: 足迹公开状态机（POST 扩展 + PATCH 编辑）

**Files:**
- Modify: `apps/api/src/routes/footprints.ts`
- Test: `apps/api/test/footprints.test.ts`（追加）

**Interfaces:**
- Consumes: S1 的 `publicRequestedAt`；既有 `requireUser`、footprint include 形状（id/placeId/text/date/visibility/reviewStatus/likeCount/viewCount/createdAt/place{id,name}/photos[{id,takenAt}]）。
- Produces: `PATCH /footprints/:id`；`POST /footprints` body 新增 `visibility`。iOS I3 消费。

**行为契约：**

- `POST /footprints` body 增可选 `visibility: "PRIVATE" | "PUBLIC"`（默认 PRIVATE）。若 PUBLIC：`reviewStatus=PENDING`、`publicRequestedAt=now()`。
- `PATCH /footprints/:id`（requireUser，属主校验，非属主/不存在一律 404 `not_found`）。body：`{ text?: string|null, date?: ISO8601, visibility?: "PRIVATE"|"PUBLIC" }`，至少一键否则 400。
- 状态机语义（按此顺序判定）：
  1. `visibility` 切到 PUBLIC（无论原值）→ `reviewStatus=PENDING`、`publicRequestedAt=now()`。
  2. `visibility` 切到 PRIVATE → 只改 visibility（reviewStatus 原样保留）。
  3. 未动 visibility 但改了 text 或 date，且当前 `visibility=PUBLIC` → `reviewStatus=PENDING`、`publicRequestedAt=now()`（防审后偷换）。私密态改内容不触碰审核字段。
- 响应：与 POST 相同的完整足迹形状（200）。

- [ ] **Step 1: 写失败测试** — 追加用例：
  | 用例 | 断言 |
  |------|------|
  | POST 带 visibility=PUBLIC | 201，reviewStatus=PENDING，publicRequestedAt 非空 |
  | PATCH 改 text（APPROVED 公开态，先直改 DB 造 APPROVED） | 200，reviewStatus 回 PENDING，publicRequestedAt 被刷新 |
  | PATCH 只改 date（私密态） | 200，reviewStatus 不变 |
  | PATCH visibility=PUBLIC | reviewStatus=PENDING |
  | PATCH visibility=PRIVATE（原 APPROVED） | visibility=PRIVATE 且 reviewStatus 仍 APPROVED |
  | 非属主 PATCH | 404 |
  | 空 body | 400 invalid_body |
- [ ] **Step 2: 跑测试确认失败** — Run: `pnpm -C apps/api exec vitest run test/footprints.test.ts`；Expected: 新用例 FAIL（404 路由不存在）

- [ ] **Step 4: 跑测试确认通过** — 同 Step 2 命令；Expected: PASS
- [ ] **Step 5: 全量 + Commit** — `pnpm -C apps/api exec vitest run` 全过后 commit：`feat(api): 足迹公开状态机（POST visibility + PATCH 编辑触发重审）`

### Task S6: 旅程划界纯函数（关闭规格书 Q7）

**Files:**
- Create: `apps/api/src/trips/segment.ts`
- Test: `apps/api/test/segment.test.ts`（纯单测，不连 DB）

**Interfaces:**
- Consumes: 无（纯函数）。
- Produces（S7 消费）：
  ```ts
  export type SegmentInput = { footprintId: string; date: Date; cityKey: string; cityLabel: string }
  export type TripSuggestion = { footprintIds: string[]; suggestedTitle: string; startDate: Date; endDate: Date }
  export function segmentTrips(footprints: SegmentInput[]): TripSuggestion[]
  ```
  cityKey/cityLabel 由调用方解析（CITY 级祖先，无则回退 place 自身 id/name）。

**行为契约（规格 §7 全文规则）：**

1. 常驻城市 = 覆盖**去重日期天数**最多的 cityKey；并列取足迹总数多者，再并列取 cityKey 字典序小者（确定性）。仅当全体足迹去重日期总天数 ≥ 7 才判定；判定后该 cityKey 的足迹全部排除。
2. 其余足迹按 date 升序，相邻**日历日差 ≤ 2**（按日粒度：同日=0、隔一天=2 仍同组、隔两天=3 断开）归同一旅行。
3. 组内足迹数 ≥ 2 才输出；输出按 startDate 倒序。
4. 标题：城市按组内首现顺序去重；≤2 个全列（「·」连接），>2 取前 2 + `等n地`（n=城市总数）；后缀 `·YYYY年M月`（startDate 的年月）。示例：`济南·青岛·2024年5月`、`济南·青岛等4地·2024年5月`。
5. 输入空/全被排除 → 返回 `[]`。

- [ ] **Step 1: 写失败测试** — 全边界用例：
  | 用例 | 断言 |
  |------|------|
  | 常驻排除 | 北京 10 天日常 + 济南 3 天 → 仅济南组，北京足迹不出现 |
  | 天数不足不判常驻 | 总去重天数 6（北京 4 + 济南 2）→ 北京也参与成行 |
  | gap 边界 | 5/1、5/3 同组；5/1、5/4 断开 |
  | 成行门槛 | 孤立单足迹组被丢弃 |
  | 标题 ≤2 城 | `济南·青岛·2024年5月` |
  | 标题 >2 城 | 4 城 → `A·B等4地·YYYY年M月` |
  | 跨月取起始月 | 5/30–6/2 → `·2024年5月` |
  | 同日多足迹 | 去重天数按日计，分组含全部足迹 |
  | 输出排序 | 两段旅行按 startDate 倒序 |
- [ ] **Step 2: 确认失败** — Run: `pnpm -C apps/api exec vitest run test/segment.test.ts`；Expected: FAIL（模块不存在）
- [ ] **Step 3: 实现契约**（日粒度归一化用 UTC 日期字符串，避免时区抖动）
- [ ] **Step 4: 确认通过**；**Step 5: Commit** — 信息：`feat(api): 旅程划界纯函数（常驻排除+gap聚类+标题规则，关闭 Q7）`
